# Fast Sub Desktop UI Functional Plan

本文档记录 Fast Sub 桌面端 UI 的功能划分规划。当前阶段只讨论产品功能、用户流程和信息结构，不进行实际 UI 页面设计，也不写代码。

## 1. 产品目标

Fast Sub 桌面端应面向普通本地用户，提供一个足够简单的字幕生成工具：

- 第一次打开时，自动检查和准备本机运行环境。
- 默认准备一个可用的 ASR 模型和一个可用的翻译模型。
- 日常使用时，用户只需要添加视频或文件夹，然后点击生成。
- 复杂参数放到详细设置中，不在主界面默认暴露。
- 本地优先，除非用户明确选择远程能力，否则不上传音频或字幕。

## 2. 顶层功能区

桌面端可以先划分为以下功能区：

1. 首次启动 / 环境检查
2. 主界面 / 一键生成字幕
3. 任务进度 / 队列
4. 详细设置
5. 模型管理
6. 诊断 / 高级信息

普通用户的主路径应集中在前三个功能区。模型管理、详细设置和诊断功能应降低默认可见性，避免让用户感觉这是一个开发者控制台。

## 3. 首次启动 / 环境检查

### 3.1 目标

第一次打开 App 时，把本机能不能跑、默认能力是否准备好一次性处理完，让用户后面可以直接拖视频生成字幕。

### 3.2 检测本机环境

需要检查：

- 操作系统和 CPU 架构,可用内存,可用磁盘空间，是否存在可用 GPU / CUDA。
- FFmpeg / FFprobe 是否可用。
- Fast Sub daemon 是否可以正常启动。
- 本地 worker 运行环境是否可用。
- 模型存储目录是否存在且可写。
- 网络是否可用于首次下载模型。

这些检查应以用户能理解的文字展示，例如：

- 已就绪
- 缺失
- 正在安装
- 安装失败
- 可跳过

内部错误码可以保留在诊断详情里，不应该直接作为普通用户主文案。

### 3.3 安装 / 修复缺失依赖

如果检测到缺失项，首次启动流程应提供明确动作：

- 缺少 FFmpeg 时，提示安装或使用内置安装器。
- 缺少 FFprobe 时，随 FFmpeg 一起处理。
- 缺少本地 worker 时，自动安装或引导安装。
- 模型目录不可写时，提示更换目录。
- 网络不可用时，允许稍后下载模型。
- 安装失败时，提供重试和查看诊断。

依赖安装不应该要求用户理解 daemon、worker、provider 等内部概念。

### 3.4 配置默认参数

首次启动完成时，应写入一组可直接使用的默认参数：

- 默认字幕语言：自动识别。
- 默认输出格式：SRT。
- 默认输出位置：与源视频相同目录。
- 默认转写方式：本地 ASR。
- 默认翻译方式：本地翻译。
- 默认设备：自动选择 CPU / GPU。
- 默认输出冲突策略：文件已存在时询问。
- 默认隐私策略：本地优先，不自动上传音频或字幕。

这些默认参数后续可以在设置中修改。

### 3.5 准备默认 ASR 模型

首次启动时应下载一个可用的 ASR 模型。

建议原则：

- Round 11 默认使用 `whisper-small` 占位，后续真实接入时再确认 manifest id 和是否根据硬件推荐更小/更大模型。
- 如果本机性能较弱，可以推荐更小模型。
- 如果检测到 GPU 和足够磁盘空间，可以提示是否下载更高质量模型。
- 下载完成后需要执行 verify，确认模型可用。
- 如果用户跳过下载，主界面应明确提示“本地转写未准备好”。

### 3.6 准备默认翻译模型

首次启动时应下载一个可用的本地翻译模型。

建议原则：

- Round 11 默认使用 NLLB 占位，后续真实接入时再确认具体 manifest id、磁盘占用和安装失败文案。
- 优先覆盖常见方向，例如英文和中文互译。
- 如果模型较大，需要展示下载体积和预计时间。
- 下载完成后需要执行 verify，确认模型可用。
- NLLB 安装失败不阻断主转写流程，UI 提供稍后处理和诊断入口；主界面应标记“翻译未准备”。

### 3.7 首次启动完成状态

完成后展示环境总结：

- 本地转写：可用 / 未准备
- 本地翻译：可用 / 未准备
- FFmpeg：可用 / 缺失
- 默认 ASR 模型：已安装 / 未安装
- 默认翻译模型：已安装 / 未安装
- 远程 API：未配置 / 已配置 / 可选

完成页应提供：

- 进入主界面
- 更改默认设置
- 查看诊断详情

### 3.8 首次启动流程

```text
首次打开 App
→ 检测本机环境
→ 检查依赖
→ 安装缺失运行组件
→ 下载默认 ASR 模型
→ 下载默认翻译模型
→ 写入默认参数
→ verify 模型和依赖
→ 进入主界面
```

## 4. 主界面 / 一键生成字幕

### 4.1 目标

主界面应足够简洁，让用户不需要理解内部运行过程。

核心动作：

- 添加视频文件。
- 添加视频文件夹。
- 拖拽视频到指定区域。
- 点击生成字幕。

### 4.2 默认展示内容

主界面默认只展示：

- 拖拽区域。
- 添加视频按钮。
- 添加文件夹按钮。
- 输出位置。
- 生成按钮。
- 当前进度条。
- 完成后的打开字幕 / 打开输出文件夹入口。

不默认展示：

- daemon 状态。
- SSE events。
- job id。
- provider 内部名称。
- worker 细节。
- stage 细节。
- JSON envelope。

这些内容只应出现在诊断或高级信息中。

### 4.3 输出行为

默认输出：

- 生成 `.srt` 文件。
- 输出到源视频所在目录。
- 文件名默认与源视频一致。

如果输出文件已存在：

- 默认询问用户。
- 可在详细设置中改为自动覆盖或自动跳过。

## 5. 任务进度 / 队列

### 5.1 目标

任务队列用于让用户知道当前处理情况，但不暴露内部状态机。

### 5.2 普通用户可见状态

建议普通状态：

- 等待中
- 正在生成
- 已完成
- 已失败
- 已取消

内部状态如 `created`、`queued`、`running`、`canceling`、`succeeded`、`failed`、`canceled`、`interrupted` 可以保留在诊断中。

### 5.3 队列操作

支持：

- 取消当前任务。
- 移除等待中的任务。
- 重试失败任务。
- 打开完成结果。
- 打开输出文件夹。

首版可以默认限制同时运行一个任务，其余任务进入队列。

## 6. 详细设置

详细设置应默认折叠，只在用户需要时展开。

可配置项：

- 语言：自动识别 / 指定语言。
- ASR 模型。
- 翻译模型。
- 转写方式：本地 / 远程。
- 翻译方式：本地 / 远程。
- 设备：自动 / CPU / GPU。
- 输出格式。
- 输出位置。
- 输出冲突策略。
- 是否生成词级时间戳。
- 是否保留临时文件。

远程能力必须明确标识会上传音频或文本，不能隐式启用。

## 7. 模型管理

模型管理用于查看和维护本地模型。

功能包括：

- 查看已安装 ASR 模型。
- 查看已安装翻译模型。
- 下载推荐模型。
- 删除本地模型。
- 验证模型是否可用。
- 查看模型占用空间。
- 更改模型存储位置。

模型管理不应阻塞主流程。首次启动会准备默认模型，后续用户可在这里扩展。

## 8. 诊断 / 高级信息

诊断区面向排障和开发，不作为普通用户主界面。

可包含：

- daemon ready 状态。
- base URL。
- token redacted 状态。
- provider 状态。
- model verify 状态。
- job id。
- job 原始状态。
- redacted logs。
- structured error。
- 最近 SSE events。

诊断区应遵守隐私规则：

- 不展示完整 token。
- 不展示 API key。
- 不展示 Authorization header。
- 不展示 signed URL credential。
- provider 原始敏感响应必须脱敏。

## 9. 隐私原则

默认行为：

- 本地转写。
- 本地翻译。
- 不自动上传音频。
- 不自动上传字幕。
- 不自动启用远程 provider。

当用户选择远程能力时，需要明确说明：

- 会上传什么内容。
- 上传到哪个 provider。
- 需要什么 API key。
- 是否会产生费用。

## 10. 后续待定问题

以下问题后续需要产品和技术一起确认：

- 默认 ASR 真实 manifest id，以及是否根据硬件推荐更小/更大模型。
- 默认 NLLB 真实 manifest id、磁盘占用提示和安装失败文案。
- 是否内置 FFmpeg，还是引导用户安装。
- 模型下载失败后的离线体验。
- 是否支持批量翻译已有 SRT。
- 主界面是否同时支持“只转写”和“转写后翻译”。
- 远程 provider 是否默认隐藏。
- 模型体积和下载时间如何展示。

## 11. UI Scope Decisions

以下决策用于约束当前桌面 UI 原型，避免子功能和诊断能力干扰普通用户主流程。

### 11.1 Daemon 启动和异常恢复

daemon ready、token、SSE 重连、`events_lost`、restart recovery 等技术细节只记录在诊断日志中。

面向用户的异常处理应保持简单：

- 显示“Fast Sub 服务暂时不可用”。
- 提供“一键修复”按钮。
- App 自动重启本地服务并重新同步任务状态。
- 技术日志可折叠查看，但不作为默认内容展示。

### 11.2 已有 SRT 翻译

已有 SRT 翻译作为独立子功能，不影响“拖入视频 → 生成字幕”的主流程。

需要覆盖：

- 导入 `.srt`。
- 源语言 / 目标语言。
- 替换 / 双语输出。
- 双语顺序。
- 本地、网页、API 翻译方式。
- checkpoint / resume。
- partial failure 保留原文并写 `.errors.json`。

### 11.3 字幕烧录 Burn-in

字幕烧录也是独立子功能，不放进主流程默认路径。

需要覆盖：

- 选择视频。
- 选择字幕。
- 字体、字号、编码 preset。
- 输出 `.subtitled.mp4`。
- 烧录进度。
- 打开输出文件夹。

### 11.4 Analyze 参数

媒体预分析、音频流、VAD、速度/质量模式等参数放在详细设置中。

默认值由系统推荐，用户不需要强制选择。

### 11.5 Benchmark

Benchmark 暂不进入第一版主功能。

设置/诊断后面保留一个规划入口即可，后续再扩展：

- RTFx、耗时、worker 耗时。
- WER / CER。
- 字幕健康度。
- 翻译 BLEU / chrF / exact match。
- JSON / Markdown 报告。

### 11.6 Provider 管理

Provider 管理需要补充完整状态，但仍属于设置/高级区域。

需要展示：

- STT provider。
- Translation provider。
- local / api / web / native 分类。
- 可用性状态。
- 隐私说明。
- 是否支持批量、词级时间戳。
- 静态检查，不默认联网或上传。

### 11.7 模型安装状态

模型安装细节写入日志。

面向用户只展示简单状态：

- 已安装。
- 未安装。
- 安装中。
- 安装失败。

失败时提供“一键重新安装”和“查看日志”。

### 11.8 API 服务细节

API 服务设置中需要覆盖：

- API key 环境变量名，而不是原始 key。
- Base URL。
- 显式模型选择。
- 上传格式：auto / m4a / mp3 / wav。
- 词级时间戳策略。
- 静态检查 / Live 测试区分。
- 上传前确认。
- 费用 / 用量提示。

### 11.9 输出类型

主流程提供一个轻量输出类型选项，默认是“原字幕”。

可选项：

- 原字幕。
- 翻译字幕。
- 双语字幕。
- 烧录视频。

复杂配置进入详细设置或独立子功能。

### 11.10 配置系统

配置系统不单独暴露成技术页面。

用户在设置页修改配置；底层再映射到：

- App 设置。
- `fast-sub-go.toml`。
- 环境变量名。

可以提供导入、导出、恢复默认，但不要求普通用户理解配置文件格式。
